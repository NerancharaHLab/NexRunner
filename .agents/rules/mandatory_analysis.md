# กฎบังคับในการทำงาน (Mandatory Execution Rules)

## กฎบังคับ
- **ห้ามลงมือ implement งานที่ไม่ใช่เรื่องเล็กน้อยทันที ต้องวิเคราะห์และถามให้เคลียร์ก่อนเสมอ** — เข้าเงื่อนไขข้อใดข้อหนึ่งต่อไปนี้ถือว่า "ไม่เล็กน้อย" ต้องหยุดคิด/ถามก่อน ไม่ใช่เริ่มเขียนโค้ดเลย:
  - แตะมากกว่า 2-3 ไฟล์ หรือมีผลกับสถาปัตยกรรมที่มีอยู่ (schema, node ใหม่ในกราฟ, endpoint ใหม่, auth flow ฯลฯ)
  - มีทางเลือก/แนวทางที่ถูกต้องได้มากกว่า 1 แบบ (เช่น เลือก library, เลือกรูปแบบ auth, เลือก state shape)
  - requirement ที่ให้มายังไม่ชัดพอจะลงมือได้ (ขาดรายละเอียดสำคัญ, ใช้ศัพท์ที่ตีความได้หลายแบบ, หรือขัดแย้งกับของที่มีอยู่จริงในโค้ด/ระบบ — เช่นเคยเจอ state ชื่อ "Ready for QA" ที่ไม่มีอยู่จริงในทีม TMH)
  - เป็น action ที่ย้อนกลับยากหรือกระทบข้อมูลจริงภายนอก (เขียนข้อมูลจริงลง Linear, ลบ/เขียนทับของเดิม, deploy จริง)
  - ทำแนวทางไปแล้วครึ่งทางเจอว่าของจริงไม่ตรงกับที่ premise ไว้ตอนแรก (เช่น library มี API ต่างจากที่คิด, service มี state ไม่ตรงที่คาด) — ต้องหยุดแล้วถามใหม่ ไม่ใช่เดาต่อเอง
  - เมื่อเข้าเงื่อนไขข้างต้น: ใช้ `AskUserQuestion` ถามเลือกแนวทาง/ยืนยันสมมติฐานที่ไม่ชัดก่อนเขียนโค้ด และใช้ `EnterPlanMode` สำหรับงานที่ต้องออกแบบหลายไฟล์/กระทบสถาปัตยกรรมจริง ก่อนเริ่มเขียนโค้ด
  - งานเล็ก ๆ ที่ชัดเจนอยู่แล้ว (แก้ bug ตรงจุด, พิมพ์ผิด, ทำตาม spec ที่ระบุครบถ้วนไม่กำกวม) ไม่ต้องถาม ทำได้เลยตามปกติ — กฎนี้ไม่ได้ให้ถามทุกเรื่องจนกวนใจ แค่กันการลงมือทำไปโดยไม่วิเคราะห์ก่อนในจุดที่มีความเสี่ยงจริง

- **สร้าง/แก้ไข UI ทุกครั้งต้องอ่าน skill `datatest-id-standard` ก่อนเสมอ** (`.agents/skills/datatest-id-standard/SKILL.md`) — ทุก element ที่ต้องกดหรือ assert ได้ (ปุ่ม, input, select, table row, modal ฯลฯ) ต้องใส่ `data-testid` ตาม pattern `[module]:[component]:[element]__[modifier]` ที่ระบุไว้ในนั้น ห้ามตั้งชื่อ `data-testid` เอาเองโดยไม่ผ่าน skill นี้ ไม่ว่าจะเขียน UI ใหม่ในโปรเจกต์นี้ (เช่น `web/`) หรือแก้ของเดิม

- **การสร้างสคริปต์ชั่วคราว (Temp/Helper Scripts) ห้ามสร้างไว้ที่ Root ของโปรเจกต์** — สคริปต์ช่วยเหลือ, สคริปต์เจนเนอเรต, สคริปต์ย้ายข้อมูล หรือสคริปต์ทดสอบชั่วคราว (เช่น `.py`, `.sh`, `.js` ชั่วคราว) ต้องถูกสร้างและจัดเก็บไว้ในโฟลเดอร์ `temp_scripts/` เสมอ เพื่อรักษาความสะอาดของโครงสร้าง Root ของโปรเจกต์
